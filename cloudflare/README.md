# Личный Cloudflare Worker

Этот вариант нужен, когда оператор блокирует стандартные адреса Telegram и общие CF-домены. Личный домен Worker должен быть доступен из вашей мобильной сети; если заблокирован и он, этот способ не гарантирует подключение.

## Через панель Cloudflare

1. Войдите в свой аккаунт на [dash.cloudflare.com](https://dash.cloudflare.com/). Если аккаунта нет, создайте и подтвердите почту самостоятельно. Выберите план Workers Free; платный план для этого примера не требуется. Не включайте платные дополнения.
2. Откройте **Workers & Pages → Create application → Create Worker / Hello World**. Назовите Worker, например `tg-ws-bridge`, и создайте его. Названия кнопок могут меняться.
3. Откройте **Edit code**, полностью замените исходник содержимым [worker.js](worker.js) и нажмите **Deploy**.
4. В приложении Android `.3` откройте **Настройки → Создать ключ Worker → Скопировать ключ Worker**. В Cloudflare у Worker откройте **Settings → Variables and Secrets**, добавьте **Secret** с именем `AUTH_TOKEN` и вставьте скопированный ключ. Сохраните и разверните изменение. В GitHub этот ключ не добавляйте.
5. Скопируйте адрес Worker вида `tg-ws-bridge.имя-аккаунта.workers.dev`. В настройках Android вставьте его в **Личный Cloudflare Worker** без `https://`, оставьте тот же ключ и нажмите **Сохранить**. Затем запустите прокси и подключите Telegram.

Поле **Свой CF-домен** — другой, старый тип маршрута; адрес Worker следует вводить именно в поле **Личный Cloudflare Worker**.

Если Worker задан, приложение направляет через него все поддерживаемые DC. Чтобы вернуться к стандартному режиму, остановите прокси и очистите адрес Worker. Секрет локального MTProto-прокси при этом не меняется.

## Через Wrangler

В этом каталоге уже есть конфигурация. Если вы предпочитаете CLI, войдите и разверните Worker официальным [Wrangler](https://developers.cloudflare.com/workers/wrangler/):

```sh
npx wrangler login
npx wrangler secret put AUTH_TOKEN
npx wrangler deploy
```

В приглашение `secret put` вставьте ключ из приложения. Вход и разрешение доступа к Cloudflare выполняются владельцем аккаунта. Не сохраняйте Cloudflare API-токены в файлах проекта.

## Что проверяет Worker

- Обслуживает мост только по `/apiws` и только с правильным заголовком `Authorization: Bearer …`.
- При отсутствии `AUTH_TOKEN` мост выключен и отвечает `503`.
- Разрешает подключения только к известным адресам Telegram DC1–DC5/DC203 на порту 443. Произвольный TCP-прокси не создаётся.
- Сохраняет порядок бинарных кадров и закрывает обе стороны при разрыве.
- Не журналирует содержимое трафика или ключ доступа. Worker передаёт уже зашифрованные MTProto-данные; он не входит в аккаунт Telegram.

Обычный запрос к `/` показывает только страницу состояния. Это проверяет доступность HTTPS, но не подтверждает прохождение MTProto. Полная проверка делается через приложение и `android/tools/probe_proxy.py`.

## Лимиты и проверки

У Workers Free есть [лимиты Cloudflare](https://developers.cloudflare.com/workers/platform/limits/), включая 100 000 запросов в день и ограничения CPU. Это не безлимитный сервер и не гарантия обхода ограничений оператора. [TCP sockets](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/) — штатный API Cloudflare для исходящего соединения с Telegram.

Локальные контрактные тесты:

```sh
node --experimental-vm-modules --test cloudflare/worker.test.mjs
```

Они проверяют авторизацию, разрешённые назначения, порядок данных и закрытие потоков с имитацией Cloudflare API. Они не заменяют развёртывание и проверку из мобильной сети.
