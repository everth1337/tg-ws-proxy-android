# TG WS Proxy для Android

Неофициальный Android-порт [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy), основан на коммите `6690b78` (ядро 1.11.4). Лицензия исходного проекта — MIT; см. `../LICENSE`.

## Установка и подключение

Требуется Android 7.0+ и 64-битная архитектура ARM64 или x86_64. Сборка APK предназначена для ручной установки и тестирования, подписана локальным отладочным ключом. Это не официальный релиз Flowseal.

1. Установите APK и откройте TG WS Proxy.
2. Нажмите «Запустить прокси». Разрешите уведомления, чтобы видеть службу и кнопку остановки.
3. Нажмите «Подключить Telegram» и подтвердите использование прокси в Telegram.
4. При ограничении фоновой работы откройте «Фоновая работа» и разрешите приложению работать без ограничений батареи. Названия настроек зависят от производителя.

Прокси слушает только `127.0.0.1:1443` на самом телефоне. Он не предоставляет доступ другим устройствам в сети. Секрет создаётся при первом подключении и сохраняется в закрытых настройках приложения. Порт и свой CF-домен можно поменять после остановки службы. Перед удалением приложения или после остановки службы отключите этот прокси в Telegram.

## Реализация

- Нативный интерфейс Android на Java; foreground service с постоянным уведомлением и действием остановки.
- Исходное Python-ядро копируется из `../proxy` задачей `syncProxyCore`. Настольный интерфейс и его зависимости не включаются.
- Python 3.13 встроен через Chaquopy 17.2.0. AES-CTR реализован адаптером к системному `javax.crypto.Cipher`, без установки настольного пакета cryptography.
- Сохраняются WS, CF fallback, HTTP/2 для медиа и TCP fallback исходного ядра. По умолчанию используются штатные маршруты DC2/DC4 и размер пула 4: это важно для одновременных подключений Android-клиента.
- Служба запускается пользователем, автоматически после перезагрузки не включается. Во время работы удерживается partial wake lock; это расходует батарею. Производитель телефона всё равно может завершить процесс.
- Начиная с `1.11.4-android.2`, служба отслеживает [изменение сети по умолчанию](https://developer.android.com/develop/connectivity/network-ops/reading-network-state). При смене Wi-Fi/мобильной сети, IP или DNS она закрывает старые клиентские соединения, сбрасывает пулы и задержки повторных попыток, затем вновь открывает тот же локальный порт с прежним секретом. Повторные события одной смены сети объединяются. Кнопка «Переподключить» выполняет такое же восстановление вручную.
- Состояние «Прокси работает» означает, что локальный порт слушает подключения; доступность маршрутов зависит от сети.
- Это не VPN. Прокси нужно включить в настройках Telegram. Приложение не требует входа в аккаунт Telegram.
- В журнале скрываются ссылка и секрет подключения. Журнал ограничен по размеру и хранится в памяти процесса.

## Сборка

Нужны JDK 21, Android SDK platform 36.1 и Python 3.13 на компьютере. Откройте каталог `android` в Android Studio или задайте путь к SDK в `local.properties` (в Windows используйте `sdk.dir=C\:/.../Android/Sdk`).

```powershell
$env:JAVA_HOME='C:\Program Files\Java\jdk-21.0.12'
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

## Проверки

```powershell
adb -s SERIAL install -r app/build/outputs/apk/debug/app-debug.apk
adb -s SERIAL install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s SERIAL shell am start -n org.flowseal.tgws.android/.MainActivity
adb -s SERIAL shell am instrument -w org.flowseal.tgws.android.test/androidx.test.runner.AndroidJUnitRunner
```

Instrumentation проверяет потоковый AES-CTR на векторе NIST, два запуска службы, доступность локального порта и его закрытие после остановки.

В версии `.2` дополнительно проверяются пересоздание слушателя и закрытие старого клиентского сокета при переподключении. Для проверки системного переключения Wi-Fi → мобильная сеть → Wi-Fi на выделенном эмуляторе:

```powershell
adb -s SERIAL shell am instrument -w -e network_handover true org.flowseal.tgws.android.test/androidx.test.runner.AndroidJUnitRunner
```

Этот сценарий временно отключает Wi-Fi и включает его обратно в `finally`. Не запускайте его через Wi-Fi ADB на физическом телефоне; для проверки телефона нужен USB. Эмулируемая мобильная сеть проверяет обработку Android-событий, но не фильтрацию оператора.

После запуска прокси через интерфейс можно проверить реальные ответы Telegram без авторизации в аккаунт:

```powershell
python -m pip install cryptography
python tools/probe_proxy.py --serial SERIAL
```

Проверка отправляет `req_pq_multi` через MTProto и сверяет тип ответа `resPQ` и случайный nonce для каждого DC1–DC5. Секрет читается через ADB `run-as` только у отладочной сборки, в вывод не попадает. Временное перенаправление порта удаляется по завершении проверки.

Успешный сетевой тест подтверждает прохождение MTProto, но сам по себе не проверяет вход в аккаунт, звонки, загрузку больших медиа и многочасовую фоновую работу.
